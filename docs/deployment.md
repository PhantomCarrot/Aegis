# Deployment

## What this is

Aegis is made of two services that never run on the same machine by default: the frontend (Vercel, public) and the backend (self-hosted, near the infra it controls). This doc covers how to connect them in production. See [`architecture.md`](architecture.md) for why this separation exists.

**These steps require your own Cloudflare and Vercel accounts — they can't be automated from this repo.**

## 1. Expose the backend (Cloudflare Tunnel)

The backend must never open a public port directly. Cloudflare Tunnel (`cloudflared`) connects to it outbound — free, with no usage limit for the tunnel itself (see the discussion in the implementation plan: only the Zero Trust/Access layer, optional and not needed here, is paid beyond 50 accounts).

```bash
# On the machine hosting the backend (local or remote)
brew install cloudflared        # or the install method matching your OS

cloudflared tunnel login
cloudflared tunnel create aegis-backend
cloudflared tunnel route dns aegis-backend aegis-backend.yourdomain.com

# Point the tunnel at the local backend
cloudflared tunnel run --url http://localhost:8766 aegis-backend
```

For a service that runs continuously (not just a test), use a config file (`~/.cloudflared/config.yml`) and a system service (`cloudflared service install`) instead of `tunnel run` in the foreground — see the [official Cloudflare docs](https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/).

`docker-compose.yml` includes an optional (commented) `cloudflared` service — uncomment it and set `CLOUDFLARE_TUNNEL_TOKEN` (generated by `cloudflared tunnel token aegis-backend`) if you'd rather drive everything from Docker Compose.

## 2. Configure the backend

```bash
# Token(s) the frontend will need to present — generate a long random value
AEGIS_BACKEND_TOKENS=<generated-token>

# The frontend's real origin once deployed (replaces the localhost default)
AEGIS_ALLOWED_ORIGINS=https://your-project.vercel.app
```

## 3. Deploy the frontend (Vercel)

- New Vercel project, **Root Directory** = `frontend/`.
- Environment variables (Vercel → Settings → Environment Variables, **never prefixed `NEXT_PUBLIC_*`** — see [`architecture.md`](architecture.md) for why the BFF proxy exists):
  - `AEGIS_BACKEND_URL` = `https://aegis-backend.yourdomain.com` (the tunnel's hostname)
  - `AEGIS_BACKEND_TOKEN` = the same token as `AEGIS_BACKEND_TOKENS` on the backend

## 4. Verification

1. `curl -H "Authorization: Bearer <token>" https://aegis-backend.yourdomain.com/healthz` → should also pass without the header (public endpoint).
2. Open the deployed frontend, check the "Backend connected" badge on the home page.
3. Ask a question in the chat — the SSE stream must work through Vercel → tunnel → backend without being buffered (see the note on the proxy in `architecture.md`).

## Alternatives to Cloudflare Tunnel

If you'd rather avoid a Cloudflare account: a self-hosted reverse tunnel (`frp`, `rathole`) to a small VPS you control also works — same principle (outbound connection, no inbound port), just more pieces to operate yourself. Not documented here in detail — set up your own tunnel service and point `AEGIS_BACKEND_URL` at it.
